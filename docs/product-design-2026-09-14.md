# 案头 DeskQuote · 产品与设计说明

> 2026-09-14 · macOS 常驻桌面卡片挂件 · 孙子兵法 / 庄子 / 墨子 / 王阳明心学 / 毛泽东选集

---

## 一、这个产品真正要解决的问题

表面需求是「桌面上显示一句名言」。但这类产品 90% 的失败不是做得丑，是**语义疲劳**：第三天起眼睛自动跳过它，挂件退化成壁纸的一部分。

所以设计的第一目标不是「好看」，是**维持可见性（salience）**。所有关键决策都从这一条推出：

| 设计决策 | 推理 |
|---|---|
| 默认 45 分钟才换一句 | 3 秒换一句等于没读。45 分钟 × 一个工作日 ≈ 10 句，是能被记住的量级 |
| 释义默认常显 | 这五本都是文言。没有释义时卡片只是装饰，不构成输入——这是实机反馈后翻掉的一个错误默认值 |
| 单击卡片立刻换下一句 | 想看的时候零摩擦，这是最高频交互，不能藏进菜单 |
| 五本书五套纸色 + 五套字体 | 换书要制造**视觉突变**打破习惯化，让人「感到换了个人在说话」 |
| 无放回洗牌而非朴素随机 | 朴素 random 会连续重复、也会让部分句子几个月不出现，两种情况都直接造成疲劳 |
| 不做通知推送 | 挂件的本分是「被看到」，不是「打断」。一旦打断就会被关掉 |

## 二、反功能（明确不做）

- **不做 AI 生成句子** —— 语料的权威性是这个产品的全部价值，生成即毁灭。
- **不做云同步 / 账号** —— 本地 JSON 足够，任何登录都是净负价值。
- **不做 WidgetKit 通知中心小组件** —— 刷新受系统预算控制（最快约 15 分钟且系统可延迟），点击只能 deep link 无法即时换句。核心交互被杀死，形态即错。
- **不做插画人物** —— 参考图里的人物像会抢走对文字的注意力，且风格难统一。改用纸纹 + 书法字体 + 印章建立东方感。
- **不做「今日运势」式包装** —— 这三本书是工具书不是心灵鸡汤，包装错了会让人不敢在同事面前打开。

## 三、形态与层级（关键产品决策）

无边框 SwiftUI 卡片浮窗，窗口层级可切：

- **悬浮层 `floating`**（默认）：永远在最上层，工作时余光可扫到。非激活状态 92% 不透明度，鼠标悬停升到 100%，不抢键盘焦点。
- **桌面层 `desktop`**：贴在墙纸上，被所有窗口遮住。适合「整理桌面 / 切换 Space 时看到」的低干扰用法。

App 以 `LSUIElement` 运行（不占 Dock、不占 ⌘Tab），只在菜单栏留一个入口。

## 四、交互模型

| 操作 | 行为 |
|---|---|
| 单击卡片 | 下一句 |
| 拖动卡片 | 移动位置（自动记忆） |
| ⌥ 单击 | 展开 / 收起释义 |
| 右键卡片 / 点菜单栏 | 完整菜单 |
| ⌃⌥Space（全局） | 换一句 |
| ⌘C（卡片聚焦时） | 复制「原文 —— 出处」 |

菜单提供：换一句 · 书目过滤（三本可多选）· 轮换间隔 · 窗口层级 · 明暗主题 · 卡片宽度 · 开机自启 · 收藏本句 · 只看收藏。

## 五、抽样算法

朴素随机会产生两种体验事故：连着两次抽到同一句，以及某些句子几个月不出现。

第一版用「冷却队列」挡住了前者，但自测暴露了它挡不住后者——它仍是有放回抽样，224 条抽 4000 次时最少的出现 9 次、最多的 27 次，给不出「每句多久必然出现一次」的保证。改为**无放回洗牌袋**：

1. 把当前候选池洗成一副牌，依次发完再重洗。
2. 重洗时把上一句挪开，杜绝跨轮相邻重复。
3. 牌堆持久化到 UserDefaults，退出重开接着发，不会因重启丢掉均匀性。
4. 候选池变化（切换书目 / 只看收藏）时剔除已不在池中的牌，不重置进度。

实测（224 条抽 4480 次）：每句恰好出现 20 次，零立即重复，两次出现的最大间隔 446 ≤ 理论上限 2N−1 = 447。

## 六、视觉语言

核心手法：**同一套版式骨架，三套完全不同的纸墨**。读者不需要看书名就知道是谁在说话。

| | 孙子兵法 | 庄子 | 墨子 | 王阳明心学 | 毛泽东选集 |
|---|---|---|---|---|---|
| 气质 | 冷峻 · 简 | 旷达 · 逸 | 质朴 · 工 | 清雅 · 松 | 沉厚 · 力 |
| 纸色（浅） | `#EFE9DA` 竹简麻黄 | `#F2F5F3` 天水青白 | `#EEECE5` 素麻灰 | `#FAF6ED` 宣纸米白 | `#F6F1E7` 毛边纸暖白 |
| 纸色（深） | `#232A33` 玄青 | `#1E2B2D` 苍青 | `#22262B` 铁墨 | `#262E2D` 苍墨 | `#2A2320` 深褐 |
| 朱印 / 强调 | `#8C3B2E` 朱砂 | `#3F6E78` 青 | `#455E71` 铁青 | `#45695B` 青碧 | `#A62B20` 正红 |
| 书名字体 | 隶书 Libian SC | 行楷 Xingkai SC | 粗宋 Songti SC Black | 楷书 STKaiti | 魏碑 Weibei SC |
| 正文字体 | Songti SC | Songti SC Light | Songti SC | STKaiti | STFangsong（《毛选》原书正文体）|
| 闲章 | 诡道 | 逍遥 | 兼爱 | 知行 | 求是 |

五本书的书名字体两两不同（隶 / 行楷 / 粗宋 / 楷 / 魏碑），各有所指，不是为了好看而随机换。

**排版规则**

- 字号按字数自适应：≤12 字 → 30pt，≤24 → 25pt，≤48 → 20pt，>48 → 17pt。保证长短句都填满视觉重心。
- 中文必须加字距 `tracking +1.2`，否则宋体在小字号下糊成一团。
- 行高 = 字号 × 1.72。中文行距比西文需要更松。
- 短句（≤14 字且无标点断句）自动**竖排**，长句横排。竖排是这三本书最本来的样子，也是最强的视觉记忆点。
- 纸纹用预生成噪点位图缓存，不用逐帧 Canvas 重绘（否则常驻挂件会持续吃 CPU）。

## 七、语料与校验

224 条，每条都带释义。`Resources/corpus.json` 结构：

```json
{ "book": "sunzi", "text": "知彼知己，百战不殆。",
  "source": "孙子兵法·谋攻篇", "note": "释义",
  "verified": { "witness": "维基文库《孫子兵法》", "section": "谋攻第三" } }
```

**收录原则**：只收能定位到原书的句子。网络流传但定位不到出处的（如「越是艰难处，越是修心时」「此心不动，随机而动」）一律不收——这个产品的信用全押在这一点上。

**校验方式**：语料由模型知识写出，再逐条与维基文库的公有领域底本做**去标点全文比对**，篇目归属以底本为准。校验器抓出的问题包括：

- 一条义理级错误：墨子「执**无**命者之言」应为「执**有**命者之言」（墨家主张非命，批评的是执有命者）。
- 五条篇目误植：如「人须在事上磨」我标《传习录·下》，底本在卷上；「攻吾之短者是吾师」我标《教条示龙场诸生》，实见于《传习录·中》。
- 七条孙子异文：如「唯**人**是保」底本作「唯**民**是保」、「恃吾有以待**也**」底本作「待**之**」。这类一字之差靠单一底本不能裁决，因此补了曹操注《孫子略解》作第二见证本，两本一致才改。
- 两条无法用底本支持的，直接删除（「兵无常势，水无常形」两见证本均作「兵无成势，无恒形」；墨子「俭节则昌」所在《辞过》正文未获底本）。

**当前状态：178/224 条通过原文+篇目校验。** 未校验的 46 条 = 44 条毛选（非公有领域，无可检索底本）+ 2 条王阳明《年谱》（维基文库无正文）。这两类在 JSON 里 `verified` 为 `null`，文本与出处来自模型知识，**未经原书核对**。

校验管线在 `scripts/`（`fetch_sources.py` 抓取、`verify2.py` 比对），可随时重跑。

## 八、技术栈

纯 Swift + SwiftUI + AppKit，`swiftc` 直接编译成 `.app` bundle，ad-hoc 签名，无第三方依赖、无 Xcode 工程文件。`./build.sh` 一条命令产出可分发的 App（1.7 MB）。

另有两个不依赖任何权限的验证工具：

- `scripts/preview.sh` —— 离屏把各书各排版的卡片渲染成 PNG，用于设计迭代与验收，不需要录屏授权，也不用把 App 摆到屏幕上截图。
- `scripts/SelfTest.swift` —— 语料完整性、竖排切分不丢字、抽样器的均匀性与间隔上界。
